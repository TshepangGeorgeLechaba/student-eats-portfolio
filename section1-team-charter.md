### Core Artifacts of the Team Charter

#### A. Shared Purpose & Mission Statement
"To provide CPUT students with an accessible, reliable, and affordable digital marketplace for residence-cooked meals while empowering local student vendors to build and manage micro-food businesses."

#### B. Team Core Values
1. **Transparency:** Open communication regarding task blockers, backend issues, and sprint timelines.
2. **Accountability:** Ownership of assigned Trello user stories and commit deadlines.
3. **Adaptability:** Embracing feedback during sprint retrospectives to pivot code structure or design layouts.
4. **Collaboration:** Pairing up on challenging full-stack integrations (React to Express/MySQL).

#### C. Working Agreements & Operational Rules
- **Sprint Cycle:** Bi-weekly sprint planning sessions held via Discord/Microsoft Teams.
- **Daily Communication:** WhatsApp group check-ins every weekday by 10:00 AM to report *What I did yesterday*, *What I will do today*, and *Any blockers*.
- **Version Control Rules:** 
  - Main/Production branch is protected.
  - All new features must be developed on isolated feature branches (e.g., `feature/user-auth`, `feature/cart-checkout`).
  - Pull requests require at least one code review before merging.
- **Conflict Resolution Protocol:** Direct peer-to-peer discussion first; if unresolved within 24 hours, escalated to the Project Manager for final consensus during sprint meetings.

## 2. Structured Reflection

### Reflecting on Team Alignment and Friction Reduction

Creating and maintaining our Agile Team Charter played a fundamental role in shaping how our team operated during the development of the *Student Eats* platform. In early project phases, establishing a shared purpose ensured that every team member—whether focusing on React component design or Express server routing—understood how their individual deliverables contributed to the overall user experience.

#### Key Takeaways & Impact on Execution:
1. **Establishing Working Agreements:** Setting explicit communication channels and version control rules reduced merge conflicts and eliminated ambiguity regarding task deadlines. Knowing when and where stand-ups occurred kept team members accountable throughout each sprint.
2. **Mitigating Team Friction:** When technical blockers arose—such as schema mismatches between our MySQL database and Express API endpoints—the charter’s conflict resolution protocol provided a clear, non-confrontational framework to resolve technical differences quickly.
3. **Evolution of Learning:** As a developer and project lead, formulating this social contract demonstrated that software development is as much about human alignment and clear operational guidelines as it is about writing clean code. The charter served as our team anchor when sprint deadlines were tight.
